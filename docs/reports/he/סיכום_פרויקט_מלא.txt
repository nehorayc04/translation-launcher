חלק 1 — סקירה כללית: מה זה הפרויקט
════════════════════════════════════════════════════════════════════════════

המטרה: לתרגם משחקי מחשב (ותוכנות) לעברית, ולהפיץ את התרגומים דרך אתר ציבורי +
אפליקציית לאנצ׳ר של Windows שמתקינה את המודים בלחיצה אחת.

שלושת המרכיבים:
  1. אתר ציבורי — hebrew-translation-hub.com (Vite + React + Tailwind + Supabase +
     Vercel functions). מציג קטלוג משחקים, מאפשר קנייה, הורדה, הצבעות, ביקורות,
     תרגום קהילתי, ופאנל אדמין מלא.
  2. לאנצ׳ר Windows — "Translation Manager" (Eel/Qt + React). מזהה משחקים מותקנים,
     מוריד את התרגום המתאים, ומתקין אותו לתיקיית המוד של המשחק.
  3. מנוע התרגום — סקריפטים לוקאליים שמחלצים טקסט, מתרגמים EN→עברית, ומרכיבים מוד.

הטריק המרכזי (Arabic-slot hijack): מנועי משחק כמעט אף פעם לא כוללים locale עברי, אבל
כן כוללים ערבית (RTL). שולחים את הטקסט העברי לתוך ה-slot של הערבית → מקבלים בחינם את
צינור ה-RTL/bidi הבדוק של המנוע. המשתמש בוחר "ערבית" בהגדרות המשחק, והעברית מוצגת RTL.
(במשחקים בלי slot ערבי — "LTR-slot hijack": חוטפים slot אנגלי ומאחסנים עברית VISUAL,
כלומר הפוכה מראש, כי מנוע כזה לא עושה bidi.)

המשתמש: נהוראי, מפתח מנוסה, גיל 21. תחומים: תכנות, אוטומציה, סייבר, AI. שפת עבודה:
עברית תמיד. סגנון: ישיר ותמציתי.

מצב שיטת התרגום (עדכון 2026-07-01): התרגום כבר לא רץ על מודל מקומי (gemma/qwen על

** כלל re-release (build-id self-update) **: הגרסה נשארת קבועה ומתפרסמת "in place". העדכון
העצמי משווה BUILD_ID (timestamp) ולא version. build_exe.bat צורב timestamp טרי ל-
translation_manager/_build_info.py בכל בנייה. כל re-release חייב, עם אותו build-id:
  1. build_exe.bat (צורב BUILD_ID חדש)
  2. קומפילציה של installer.iss + החלפת ה-asset ב-GitHub release (gh release upload --clobber)
  3. PATCH לשורת launcher_releases עם sha256/size/build_id החדשים; לוודא is_current=true
אם ה-BUILD_ID הצרוב וה-DB build_id מתפצלים → כל לאנצ׳ר מציג "עדכון זמין" נצחי שקרי.

** אזהרה קריטית — build_exe.bat חייב להישאר CRLF ** (זה batch של Windows). אם עורך/git
autocrlf ישכתב ל-LF — cmd מנתח שגוי בשקט, REM רצים כפקודות, והסקריפט לא באמת בונה →
סכנה של shipping build ישן בשקט. לוודא אחרי כל בנייה: BUILD_ID ב-_build_info.py הוא
timestamp טרי + ה-exe ב-dist עם mtime "עכשיו" לפני קומפילציה/פרסום.

** גוצ׳ה — הרצת build_exe.bat **: חייב להריץ דרך PowerShell call operator `& '.\build_exe.bat'`.
`cmd /c build_exe.bat` ו-Git-Bash `cmd //c` נכשלים "not recognized" במכונה הזאת גם מה-cwd
הנכון. ISCC בנתיב מוחלט: C:\Users\Nehoray_Cohen\AppData\Local\Programs\Inno Setup 6\ISCC.exe

** כלל עמידה ** ([[local-install-launcher-builds]]): שינוי בלאנצ׳ר → אוטומטית build+ISCC+
הרצת installer מקומית; לעולם לא לפרסם אלא אם המשתמש אומר "פרסם".

** winget / UniGetUI ** ([[launcher-release-checklist]]): כל release פומבי חייב גם PR ל-
microsoft/winget-pkgs. PR #400993 (1.0.2) נתקל ב-Validation-Defender-Error (false positive

    ולהגן על tokens; hand-rolled נכון רק ל-1-char neutrals → menu-proof עובר בזמן שכל הקורפוס
    שקט שגוי. ([[store-visual-use-real-uba]])

    ממראה (mirror) את ה-layout — bidi ו-mirroring עצמאיים. ([[rtl-dont-flip-direction-words]])

נשאר אנגלית = fallback עובד. ה-marker הוא מה שמפריד "הקובץ לא נטען" מ"לפונט אין glyphs".

**🔴 מחלקת כשל שקט #2 — חלונות popup (כלל עמידה: אפס popups, לעולם).**
המשתמש לעולם לא אמור לראות הבזק קונסולה. נמצאו ותוקנו שני מקורות:
1. **task שהצביע ישירות ל-`powershell.exe -File <script>.ps1`**, חוזר כל 5 דקות
   (`AC2Desktop`) = 12 הבזקים לשעה. **`-NoProfile` / `-WindowStyle Hidden` לא עוזרים** —
   מארח ה-task יוצר את הקונסולה *לפני* ש-PowerShell יכול להסתיר. תיקון = VBS בשורה אחת
   (`CreateObject("WScript.Shell").Run "powershell.exe -NoProfile -ExecutionPolicy Bypass -File ""<ps1>""", 0, False`)
   כשה-task מצביע ל-`wscript.exe "<that>.vbs"`.
2. **`Invoke-CimMethod Win32_Process Create` על console app** בתוך סקריפט self-heal פותח
   חלון גם כן. לשגר מחדש דרך `wscript.exe "<hidden.vbs>" "<run_X.bat>"` — ה-`.bat` גם
   מפנה stdout ללוג עם `>>`, מה ש-`pythonw.exe` חשוף היה זורק בשקט כשל-worker אין logging
   משלו (ל-`ac2_nim.py` אין).

`$t.Settings.Hidden = $true` מסתיר task בממשק Task Scheduler אבל **לא מדכא את הקונסולה** —
לעולם לא התיקון לבדו. **פקודת audit** (תופסת כל task שמריץ powershell/python/cmd/bat ישירות):
```powershell
Get-ScheduledTask | ?{$_.TaskPath -notlike '\Microsoft*' -and $_.State -ne 'Disabled'} |
  %{ $_.TaskName; $_.Actions | %{ '  ' + $_.Execute + ' ' + $_.Arguments } }
```
מוסתר-כברירת-מחדל הוא חלק מ"גמור" לכל task/relaunch — לא follow-up. [[run-hidden-no-popups]]

**Gate + cadence עומדים:** 🔒 ביקורת-בלבד מונוטונית — אל תאפה ואל תפרסם. תיקוני QA נצברים
ב-`cpqa_fixes.jsonl` (~48k: phrasing/gender/error/slang/foreign) לביקורת ידנית **לפני** כל
bake. לאפות רק batches שנבדקו; לפרסם רק על "פרסם" מפורש.
Pull cadence: `CPQAFleetPull` 3 דק' · `AC2FleetPull` 3 דק' · `W3qaFleetPull` 20 דק' ·
pushers 60 שנ'. ⚠️ Harness: `sleep` משורשר ב-Bash חסום — להשתמש ב-`run_in_background: true`
או לולאת `until <check>; do sleep 2; done`.

──────── 16.9 Visual LQA — גשר לכידת מסך + הקשר מגדרי (visual_bridge) ────────

`universal/visual_bridge/` — לוגר לכידת-מסך קריאה-בלבד שמכין frames של גיימפליי ל-VLM
שיבדוק גלישת טקסט על המסך, אותיות RTL הפוכות, ואי-התאמות הקשר. **agnostic למשחק** — dict
תצורה אחד משרת גם CP2077 וגם SM2.

- **`game_visual_logger.py`** — לולאת לכידה מודעת-focus. סוקר את כותרת חלון ה-*foreground*
  כל כמה שניות דרך Win32 native (`ctypes` user32: `GetForegroundWindow` +
  `GetWindowTextW`). משחק יעד ב-focus → grab → הקטנה (צלע ארוכה ≤1280) → JPEG (q70) ב-buffer
  `BytesIO` → כתיבה תחת `_archive/visual_logs/frames/<game_id>/` + שורה
  `{timestamp, game_id, frame_path, window_title, …}` ל-`_archive/visual_logs/runtime_log.jsonl`.
  אין משחק ב-focus → **מצב idle**: רק שינה, אף פעם לא לוכד מסך (0 GPU).
  `GAME_WINDOW_TITLES` ממפה `game_id` → שברי כותרת (substring case-insensitive).
- **אפס תלויות חדשות.** רק **Pillow** (כבר קיים) + Win32 דרך `ctypes` — בלי
  `pywin32`/`pygetwindow`/`mss`, מה ששומר על ניקיון ב-**Python 3.13**. `psutil` רק אם ניתן
  לייבוא (העשרת שם תהליך); היעדרו לא משנה כלום.
- **בטיחות קריאה-בלבד.** כל כתיבה עוברת `_safe_write_check()` → עצירה קשה (exit 99,
  `SystemExit`) על כל יעד מחוץ ל-`_archive/visual_logs/`. הסקריפט לעולם לא פותח/קורא/כותב
  קובץ משחק או ספיין תרגום.
- **חוסן (אחרי review).** grab→encode→write הכול בתוך try/except אחד כך ששום שגיאת I/O
  (דיסק מלא, נעילת AV/indexer) לא בורחת; `log_event` בולע OSError משלו; לגוף הלולאה
  `except Exception` רחב שרושם וממשיך. `SystemExit` מהשומר עדיין בורח בכוונה.
- **ריבוי מסכים.** ה-grab מוגבל ל-`GetWindowRect` של חלון המשחק מעל שולחן העבודה הווירטואלי
  (`ImageGrab.grab(bbox=…, all_screens=True)`), כך שמשחק במסך משני נלכד נכון; fallback לכל
  שולחן העבודה הווירטואלי אם ה-rect לא ניתן לקריאה.
- **מסך-מלא בלעדי.** לכידת GDI (ImageGrab) לא יכולה לקרוא משטח DXGI בלעדי → frame שחור לגמרי.
  מזוהה דרך קיצוני luminance (`hi==0`) ונרשם כ-`capture_failed`; **להשתמש ב-borderless windowed**.
- CLI: `selftest` (בדיקת deps/IO, בלי משחק) · `probe` (הצגת החלון הממוקד + התאמה) · `--once`
  (לכידה אחת) · `run` (הלולאה). אומת: `py_compile` נקי על 3.13.13, `selftest` PASS.

**מערכת ההקשר-המגדרי (הבקשה המקורית: להראות את ה-frame שבו מחרוזת מופיעה) — נבנתה 2026-07-06:**
1. **`frame_match.py`** — הגשר לכידה→שורה. עושה OCR לרצועת הכתוביות של frame (תחתון ~32%)
   עם **Tesseract `heb`** (`_tessdata/` עצמאי שהועתק מפרויקט Video Ai; `--tessdata-dir`,
   בלי admin/שינוי PATH), ואז **התאמה מטושטשת** (difflib על צורה עברית מנורמלת — ניקוד/
   תגים/בתי-בקרה/פיסוק מוסרים) מול ספיין ה-base+DLC כדי לזהות את ה-`(section, key)` המדויק.
   CP2077 מרנדר את עברית ה-Arabic-slot עם bidi RTL אמיתי, ולכן Tesseract מחזיר סדר LOGICAL
   שתואם לספיין. `index` עושה OCR לכל frame ב-`runtime_log.jsonl` → `frame_matches.jsonl`.
   **`selftest` PASS 5/5** (מרנדר שורות ספיין ידועות הפוך-ויזואלית → OCR heb → מתאים חזרה
   ביחס 1.00 — מוכיח את הצינור בלי גיימפליי). אפס תלויות כבדות (Tesseract subprocess + PIL +
   difflib). CLI: `python frame_match.py selftest | index | ocr <img>`.
2. **`context_review.py`** — **גלריית "טקסט + צילום מסך"**. מריץ `gender_filter` על הספיין,
   מפצל ל-**fixed-referent** (NPC/קבוצה/מכשיר — המגדר קבוע בעולם → צילום עוזר) מול
   **player-dependent** (V = you/I → המנוע פותר, אין צורך בצילום), מושך את
   femaleVariant/maleVariant ה**חיים** מהספיין הנוכחי, ופולט דף HTML RTL עצמאי אחד: לכל שורה
   — מקור EN · נ׳/ז׳ חיים (עם תג זהה⚠/שונה✓) · צירי מגדר · שאלת מגדר בעברית · רמז סצנה
   מ-secondaryKey · צילום המסך המותאם (base64) אם נלכד, אחרת placeholder "שחק כדי ללכוד" —
   כך שאותו דף מתמלא תוך כדי משחק. נבנה: **1,999 fixed-referent** (1,199 onscreens + 800

3. **`gender_filter.py`** — מסמן אילו מחרוזות אנגליות **עלולות** לדרוש בחירת מגדר/מספר בעברית

   "they"=האובייקט המתואר (מגדר קבוע ע"י שם העצם העברי, ניתן לפתרון מ-secondaryKey) או

**הצינור העובד (ניתן להרצה חוזרת בכל עת):** `translate_queue_fast.py` →

**זמן ריצה כולל ~1.6 דק' (94 שניות).** **תנאי מוקדם: Cyberpunk 2077 חייב להיות סגור.**

מ-22% ל-0.1% על ריצה מלאה של 23k):** `DYN_MAX_WORDS` 150→100; `LONG_ITEM_CHAR_THRESHOLD`

`translate_one` על שגיאת גודל-הקשר: 3 × 2ש' → **0** (`_is_context_error()` מקצר את הלולאה).
**Throughput מתמשך ~13 פריטים/דקה** (Gemma-2-27B, RX 9070, 4 workers) → 23,792 פריטים ≈

──────── 16.12 ביקורת אוניברסליות + תיקוני UX של הלאנצ׳ר (2026-06-09) ────────

**ביקורת אוניברסליות (ניידוּת) רב-סוכנית** (נתיבי-dev צרובים, גרסת/ארכיטקטורת Windows,
לוקאל/קידוד, הרשאות/רישום, תלויות משוגרות) עם אימות adversarial. **רוב הסיכונים שסומנו
אומתו כלא-בעיות:** Win7/8/8.1 כבר חסומים ע"י `MinVersion`; `certifi` משוגר ו-`requests`
עם `verify=True` משתמש בו (אין תלות ב-cert store של ה-OS); שמות משתמש לא-ASCII נתמכים
לגמרי (pathlib + `utf-8`/`utf-8-sig`, Win32 wide APIs); הפעלה ראשונה offline נופלת חזרה
לקטלוג `_bundled_games()` (build ה-Qt לעולם לא קורא לדיאלוג ה-offline של Eel); שגיאת כתיבת
הרישום של השפה כבר מוצפת דרך `langErr`; שמות mutex/event של single-instance כבר מבודדים
לכל session ע"י Windows (בלי קידומת `Global\` → Local namespace). **שלושה תיקונים אמיתיים:**
1. **`installer.iss` `MinVersion` 10.0 → 10.0.17763** (Windows 10 1809) — הרצפה ל-Qt6/
   QtWebEngine. מתחת לזה ה-Chromium המשוגר נכשל בשגיאת DLL סתומה; עכשיו המתקין מסרב בהודעה
   נקייה. 1809 מזמן EOL אז אף משתמש אמיתי לא נחסם.
2. **בדיקת כתיבוּת מקדימה** — `game_mod.is_writable(game_root)` (בדיקת `NamedTemporaryFile`
   לא-הרסנית). `main_eel._run_game_mod_install` בודק **לפני** ההורדה (הגדולה), כך שמשתמש
   לא-מוגבה שמכוון למשחק תחת `C:\Program Files` מקבל מיד הודעת "הרץ כמנהל / העבר את המשחק"
   במקום להוריד מאות MB ורק אז להיכשל בהעתקה.
3. **תקינות `game_mod.disable()`** — מסמן `installed=False` רק כשכל הקבצים באמת נמחקו.
   קודם קובץ נעול (משחק פתוח) שבר את הלולאה אבל ה-state עדיין התהפך ל-"disabled", כך
   שה-UI שיקר בזמן שהמוד נשאר על הדיסק. עכשיו נשאר "פעיל" בכשל חלקי וניסיון חוזר מנסה שוב.
**סומן ולא תוקן** (דורש נכס בתשלום, לא קוד): המתקין וה-exe **לא חתומים Authenticode** →
SmartScreen "Unknown publisher" בהורדה ראשונה (קליק אחד "Run anyway"; המוניטין מתרפא מעצמו).

**תיקוני UX של הלאנצ׳ר (2026-06-09, אותו שיגור כמו מתג השפה):**
- **סריקת כונן מלאה כבר לא מקפיאה את ה-UI.** `scan_deep` (ו-`scan_quick`) רצו סינכרונית על
  ה-GUI thread של Qt, כך שההליכה במערכת הקבצים (דקות) נעלה את כל הלאנצ׳ר. שני ה-slots
  עוברים עכשיו דרך `_run_off_thread` (scan_deep 900ש', scan_quick 120ש').
- **קליק שמאלי על ה-tray פותח את החלון.** `qt_shell/tray.py` `_on_activated` טיפל רק
  ב-`DoubleClick`; עכשיו גם `Trigger` → `show_and_activate()`.
- **קיצור דרך / הפעלה שנייה ממקדים את החלון הקיים.** שורש: `MainWindow.show_and_activate`
  היה מתודה רגילה, ולכן `QMetaObject.invokeMethod(window, "show_and_activate", …)` של
  מאזין ה-single-instance (הפעלה **לפי שם**) עשה no-op בשקט (תפריט ה-tray עבד כי הוא קורא
  ישירות). התיקון: לקשט ב-`@Slot()`. נוסף גם `_force_foreground()` (ctypes
  `ShowWindow(SW_RESTORE)` + `SetForegroundWindow`) וב-`single_instance.signal_show()`
  `AllowSetForegroundWindow(ASFW_ANY)` מהתהליך המשגר, כדי לעקוף את מניעת גניבת-הפוקוס.
- **הצגת השפה הנוכחית לכל משחק.** `_enrich_game_row` מוסיף `currentLanguage` (ממשק +
  כתוביות) דרך `game_language.get_state` — no-op לכותרים לא-נתמכים, קריאה ~1-5ms
  ל-spiderman2/cyberpunk. `Game.currentLanguage` ב-`types.ts`; `GameDetailPanel` מציג chip
  "שפה: …" בכותרת ו-"ממשק/כתוביות כעת: …" במתג השפה.
