# Anno 1800 — Hebrew translation RECON (format reverse-engineering)

On-disk facts established by direct probing of the live install + a working
pure-Python reader (`work/rda_reader.py`). All numbers here are reproducible
against the installed archives. **Read-only — nothing in the game folder was
modified.** This is the "what's in the files + how the format works" doc;
the verdict is in `FEASIBILITY.md`, the build recipe in `PIPELINE.md`.

- **Game root:** `C:\Program Files (x86)\Steam\steamapps\common\Anno 1800`
  (Steam install; Ubisoft Connect required at runtime).
- **Engine:** Blue Byte / Ubisoft proprietary ("Anno" engine, `Anno1800.exe`).
- **No anti-cheat.** Ubisoft Connect "Verify files" restores `.rda` archives but

## RDA "Resource File V2.2" format

Fully cracked; a working pure-Python (stdlib + zlib) reader is `work/rda_reader.py`,
cross-checked against the canonical RDAExplorer (`lysannschlegel/RDAExplorer`:
`RDAReader.cs` / `BlockInfo.cs` / `DirEntry.cs` / `FileHeader.cs`). Exact layout,
quoted from the reader's docstring:

### Header (792 B / 0x318)

```
magic            : 18 bytes  ASCII "Resource File V2.2"
unknown          : 766 bytes (zero padding)
firstBlockOffset : u64 LE  @ file offset 784 (0x310)  -> first block's BlockInfo
```
File data begins right after the header, at **0x318**.

### Block chain (singly-linked)

Each block is laid out `[ file-data... ][ directory ][ BlockInfo(32) ]`.
`firstBlockOffset` points at a **BlockInfo** struct; read it, process the block,
then follow `nextBlock` to the next BlockInfo, until `nextBlock == filesize`
(EOF terminator — a block whose nextBlock points at end-of-file).

### BlockInfo (32 B, at `blockOffset`)

```
flags            : u32 LE   bit0=Compressed(zlib) bit1=Encrypted
                            bit2=MemoryResident   bit3=Deleted/skip
fileCount        : u32 LE
directorySize    : u64 LE   (on-disk / compressed size of the directory blob)
decompressedSize : u64 LE   (== fileCount * 560 ; uncompressed directory size)
nextBlock        : u64 LE   (offset of the next BlockInfo, or filesize at end)
```
The directory blob lives at `[blockOffset - directorySize]` (a memory-resident
block shifts back another 16 bytes). If `bit0` is set, zlib-decompress it to
`decompressedSize`. It is `fileCount × DirEntry` records.

### DirEntry (560 B)

```
name        : 520 bytes  UTF-16LE, 260 chars, NUL-padded (in-archive path)
offset      : u64 LE   absolute file offset of this file's bytes
compressed  : u64 LE   on-disk byte length
filesize    : u64 LE   uncompressed byte length
timestamp   : u64 LE   unix time
unknown     : u64 LE
```
Per-file: read `compressed` bytes at `offset`; if the **owning block** had the
Compressed flag, zlib-decompress to `filesize`.

### Empirical confirmation

| Archive | filesize | firstBlockOffset | structure | entries |
|---|--:|---|---|--:|
| `en_us0.rda` | 1,144,616,917 | `0x443977b5` | single **uncompressed** block | **17,723** (~99.96% `.wem` Wwise audio) |
| `data0.rda` | — | — | single **uncompressed** block | **~4,848** |

- **Compression = zlib / deflate** (NOT lz4).
- The **Encrypted** flag exists in the format, but Anno 1800's base + language
  archives are **NOT encrypted** (the reader skips an encrypted block defensively;
  none are hit in practice).
- (V2.0 archives use a 20-byte block header with u32 fields; this reader and Anno
  1800 target **V2.2**.)

## Text table

- **Spine:** `data0.rda` → `data/config/gui/texts_english.xml`
  (**3,869,738 B** uncompressed) + 11 sibling `texts_<lang>.xml` files.
- **Schema** (UTF-8, CRLF, **flat** — no nested `<TextGroup>`):
  ```xml
  <TextExport><Texts>
    <Text><GUID>190465</GUID><Text>Anglerfish</Text></Text>
    <Text><GUID>100998</GUID><Text>Icebreaker</Text></Text>
    ...
  </Texts></TextExport>
  ```
- **Keying:** the numeric **GUID is shared across all languages** → EN and any other
  locale align by GUID (a parallel corpus). The translation source = the EN `<Text>`
  value; write Hebrew into the same GUID in a `texts_<lang>.xml` we ship.
- **Scope:** 28,165 EN records. Cross-language (vs German): EN 28,165 / DE 28,160,
  **28,160 shared**, **25,167 DE≠EN** (i.e. ~25k genuinely translated strings).
- **~4% of records carry inline markup / placeholders** that must be preserved
  verbatim.
- **Sample records** (GUID → EN / DE):
  - `190465` Anglerfish / Anglerfisch
  - `100998` Icebreaker / Eisbrecher
  - `101065` Expedition Lighthouse
  - `100684` Old Nate's Harbour
  - `800701` "That's the spot!"

  **FontAwesome icon webfonts** for the CEF panels — irrelevant to body text.

## UI engine split (native HUD vs CEF panels)

A key finding: Anno 1800 uses **two** UI stacks, and they matter very differently
for RTL.

- **Native engine GUI (the main HUD).** `data/ui/` across the archives is mostly
  `.dds` textures — e.g. `data2.rda` has **35,622 `.dds` + 6,374 no-extension**
  entries = UI **art**, not HTML. So the gameplay HUD is the engine's own native GUI,
  rendered with the `data/fonts/` TTFs. **Its bidi behavior is UNPROVEN** — there is
  no shipped RTL locale to inherit a tested pipeline from.
- **CEF / Chromium panels.** `data/config/http/` carries jQuery 1.12.4, jQuery-UI
  1.12.1, d3 / nvd3 / chart.js, Prism, and the debug console HTML/CSS
  (`debuginfo` / `watchwindow` / `uidebug` / `textsource`). These drive
  **statistics / charts + debug overlays + (likely) the Ubisoft Connect overlay** —
  **NOT** the gameplay HUD. Because they run in Chromium 108 with `icudtl.dat`, CEF
  panels get **free ICU bidi shaping**.

Consequence: any RTL that "just works" would be in the CEF panels; the **native
HUD** (where nearly all gameplay text lives) is the real RTL question.

## Reader & commands

Run with the repo venv: `.venv\Scripts\python.exe`. `<install>` =
`C:\Program Files (x86)\Steam\steamapps\common\Anno 1800`.

```bash
# inventory + stats (entry count, firstBlockOffset, top extensions)
python work/rda_reader.py stats   "<install>/maindata/data0.rda"

# find the text table (and any name substring)
python work/rda_reader.py grep    "<install>/maindata/data0.rda" texts_

# extract the English spine (preserves the in-archive path under <out>)
python work/rda_reader.py extract "<install>/maindata/data0.rda" texts_english.xml games/anno1800/extract
```

The extracted spine lands at:
`games/anno1800/extract/data/config/gui/texts_english.xml`

(Other commands: `list <rda>` dumps every entry.)

## Open unknowns

1. **Native-HUD bidi mode (THE gate).** No RTL locale ships, so it's unproven whether
   the native engine GUI does any bidi shaping. Either (a) it has a bidi pass we can
   feed logical Hebrew, or (b) text must be **pre-shaped / visually reversed at build
   time** (the WD2 situation), or (c) the native HUD can't render RTL at all and only
   the CEF panels can. Must be tested with a marker string in-game.
2. **Exact HUD font binding.** Which `data/fonts/` TTF the native HUD widgets actually
   bind to (so we inject Hebrew glyphs into the right file). All candidates are
   Latin+Cyrillic with zero Hebrew today.
3. **How a custom `texts_<lang>.xml` is selected.** Whether a new/overridden text file
   is keyed by `engine.ini` `"TextLanguage"`, and which locale string to target given
   there is no Arabic slot to hijack.
4. **RdaConsole/RDAExplorer repack round-trip** — only needed if the loose-file mod
   path proves insufficient; prove a packed V2.2 archive loads before relying on it.
