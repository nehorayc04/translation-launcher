# 🎛 orchestration/ — מרכז השליטה של תרגום המשחקים

שכבת ניהול עליונה אחת מעל כל המשחקים וכל הפרופילים. במקום שנהוראי יכתוב הנחיות
ידנית לכל סוכן בכל פרופיל — **Claude Code ב-MAX הוא ה"מוח" המרכזי**: מחזיק את כל
המצב, מייצר את כל ההנחיות, מנתב משימות. נהוראי רק מפעיל בפקודה קצרה.

> ⚔️ **קרא קודם את [`DOCTRINE.md`](DOCTRINE.md)** — אמנת התפעול שגוברת על הכול:
> מבצעים עד הסוף, כוח על הקשה וחיתוך על השטות, בלי פתרונות חלשים, בקרה כפולה.

## עקרונות הניהול (הוחלטו 2026-06-29)

1. **מוח אחד = סשן MAX.** סשן Claude Code אחד בפרופיל MAX מנהל הכול. שאר
   הפרופילים (PRO + סוכני Google ב-Antigravity) רק מבצעים מה שהמוח נותן.
2. **מסירה דרך קובץ — שורת מצביע אחת.** המוח כותב את ההנחיה המלאה לקובץ במאגר;
   נהוראי אומר לכל סוכן רק `קרא <קובץ> ובצע`. שורה אחת לכל סוכן, לא בלוק ענק.
   *תנאי:* אותה תיקיית פרויקט פתוחה בכל פרופיל Antigravity (הגדרה חד-פעמית).
3. **חלוקת תפקידים:** MAX = ניהול + עבודת לאנצ'ר/אתר כבדה · PRO = גיבוי כשנגמרת
   מכסת MAX · 3-5 סוכני Google = תרגום וביקורת במקביל (סלוטים מתחלפים, לא קבועים
   למשחק — `N` נקבע לכל משימה).
4. **אוטומטי כברירת מחדל, עם 3 שערי ביטחון.** אוטומטי בלי לשאול: ייצור הנחיות,
   מיזוג פלט + בדיקות מבנה, עדכון כללים משותפים, רענון לוח המצב. **דורש אישור
   מפורש שלך** רק: (א) פרסום מוד החוצה (GitHub/Worker/אתר), (ב) שיגור לאנצ'ר
   (rebuild + publish_release), (ג) מחיקה/דריסה של קבצי משחק אמיתיים.
5. **יוזמה:** בכל פתיחה המוח מסתכל על הלוח ומציע את הצעד הכי כדאי — וממתין
   לאישורך לפני ביצוע.

## גיבוי PRO (כשנגמרת מכסת MAX)

**MAX ו-PRO חולקים היסטוריית צ'אטים** (`~/.claude/projects` משותף ב-junction). לכן
כשאתה עובר ל-PRO באותו מאגר — הצ'אט והקונטקסט נטענים אוטומטית ו-PRO ממשיך מאיפה
ש-MAX עצר **בלי שתעתיק כלום**. `HANDOFF.md` הוא רק סמן-פוקוס קצר (מה הצעד הבא
המדויק), לא העתקת קונטקסט. בפרופיל PRO פשוט אמור `המשך`. פירוט: `FLEET.md`.

## איך ממשיכים בכל צ'אט-משחק (העידן החדש)

המוח המרכזי (MAX) מנתב, עוקב ומחזיק את לוח-המצב. צ'אט-משחק נפרד הוא **סשן ממוקד
אחד למשחק** — לא מוח עצמאי. כולם חולקים מקור-אמת אחד (`state.json`) ואמנה אחת
(`DOCTRINE.md`), אז אין יותר בלגן של ידע סותר.

- **צ'אט חדש** בפרויקט הזה → טוען לבד את `CLAUDE.md` + הזיכרון, כבר בעידן החדש.
- **צ'אט שכבר פתוח** → הדבק שורת-אתחול אחת (מטה) כדי לסנכרן אותו.

כל צ'אט-משחק, אחרי האתחול: פועל לפי האמנה · מעדכן את `state.json` דרך
`orchestrate.py set` כשמשתנה מצב המשחק · כפוף ל-3 השערים · לא סומך על "done" של
סוכן · מאציל תרגום לסוכני Gemini · בסוף מסכם ומציע את הצעד הבא.

**שורת האתחול (החלף `<GAME>` במזהה מהלוח):**

```
עידן חדש: קרא orchestration/DOCTRINE.md + README.md + COMMANDS.md + RULES.md, והרץ
python orchestration/orchestrate.py game <GAME>. מעכשיו אתה הסשן הממוקד של <GAME>
תחת המוח המרכזי (MAX): פועל לפי האמנה, מעדכן את state.json דרך orchestrate.py
כשמשתנה מצב, כפוף ל-3 השערים (פרסום/לאנצ'ר/קבצי משחק), לא סומך על "done" של סוכן,
מאציל תרגום לסוכני Gemini. סכם את מצב <GAME> מהלוח והצע את הצעד הבא.
```

## כללים משותפים שמתפתחים

כשמתגלה הנחיה חדשה שטובה גם למשחקים אחרים — המוח מסווג אותה (כללי מול ספציפי),
מוסיף אוטומטית ל-`RULES.md` (ולפלייבוק הכללי ב-`universal/` אם רלוונטי), ומחיל
אותה על כל הנחיה עתידית שמיוצרת. אתה רואה את התוספת ביומן `RULES.md`.

## הערה על "אוטומטי"

הלוח מתעדכן בכל פעם שסשן ה-MAX פועל (פקודה / מיזוג / `orchestrate.py`). אין
דמון רקע חוצה-פרופילים — נקודת העדכון הטבעית היא הסשן המרכזי, וזה מספיק כי כל
הניתוב עובר דרכו.
